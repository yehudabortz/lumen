# Security reports

Only the latest development version receives fixes; no stable support window is promised yet.

Do not open a public issue containing credentials, private screenshots, device addresses or an exploitable
vulnerability. Prefer [GitHub private vulnerability reporting](https://github.com/yehudabortz/lumen/security/advisories/new)
when it is enabled. On a private repository, existing collaborators can contact the owner through the repository's
private channels. If neither route is available, open a minimal issue asking for a private reporting channel;
do not include the vulnerability or sensitive details until a private channel has been established.

Describe the affected version, Android version, impact and minimal reproduction. Sanitize logs and avoid
including watch history or credentials. Reports are handled on a best-effort basis; no response deadline or bounty
is promised. GitHub-hosted secret scanning and branch protection depend on repository visibility and plan;
the checked-in scans are not a substitute for available server-side protections.
